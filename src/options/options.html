GitHub

GitHub 不是阅读站，界面是一堆产品文案。所以这里分两套做法：
· 界面文案（左侧导航、账号菜单、仓库页签、按钮）走本地词典 —— 零请求、零延迟、术语统一，翻不中的保持英文，不会出现「Home → 家」这类机翻。
· 阅读内容（仓库简介、README、Issue / PR 正文）走模型，双语对照， 并在提示词里固定「技术名词不译」：C++、Rust、Zig、Kubernetes、API、PR 等保持原样。

启用 GitHub 翻译下列各项的总开关
界面文案 导航 / 菜单 / 按钮，本地词典替换
README 与简介 走模型，术语保持原样
提交信息 文件列表右侧的「最近提交信息」列，走模型

其它网站

在任意网站页面点扩展图标 → 「翻译此网站」即可添加，添加后访问该域名会自动翻译。 通用识别靠段落结构判断正文，导航与按钮一般不会误翻，但排版特殊的站点可能翻不全。 像 Google Docs、Notion、Figma 这类画布型编辑器没有可读文本节点，加了也翻不出来。

还没有添加任何网站。

Chrome 内置本地翻译

使用 Chrome 自带的设备端翻译模型：完全离线、不限额度、不经过任何服务器， 因此也不受代理节点 IP 被 Google 风控的影响。
每个语言对是独立的模型文件，首次使用必须由你点击触发下载（浏览器规定）。 点一次下面的按钮会自动探测浏览器支持的全部语言并逐个拉下来（约 30 种， 不支持的自动跳过，已下载的不会重复下），约需 1~2 分钟。
