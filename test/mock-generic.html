Why incremental rendering breaks naive translation extensions

Modern web applications rarely reload the whole document when you navigate. Instead they patch the existing tree, recycle nodes, and stream new content into the same containers. A translation layer that walks the DOM once at page load will therefore miss everything that arrives later.

The harder problem is node reuse. A single article element that you already translated may be reassigned to display a completely different record a second later. If your asynchronous translation resolves after that swap, the result lands on the wrong element.

Too short.

The fix is cheap: before writing the translation, verify that the source text of the host still matches what you originally sent, and that the node is still attached to the document.

Any sufficiently complicated content script contains an ad hoc, informally specified implementation of a diffing algorithm.
